# grafana-mock-webhook-service

Контейнер, который шлёт на ваш сервис вебхуки в формате **Grafana Alerting** — так же, как это делает Grafana на larek.tech. Нужен, чтобы писать и проверять обработчик алертов (например, бота для Telegram) локально, без доступа к настоящей Grafana.

Алерты выдуманные, но формат совпадает с тем, что приходит из контакт-поинта типа Webhook: поля, `fingerprint`, `groupKey`, `title`, ссылки на `grafana.k.larek.tech`.

## Быстрый старт

Ваш сервис слушает `http://localhost:8080/webhooks/grafana`. Запустите мок:

```bash
docker run --rm -p 3000:3000 \
  --add-host=host.docker.internal:host-gateway \
  -e TARGET_URL=http://host.docker.internal:8080/webhooks/grafana \
  ghcr.io/egortarasov/grafana-mock-webhook-service:latest
```

- Откройте http://localhost:3000. Там можно отправить любой сценарий кнопкой, посмотреть JSON и ответы вашего сервиса.
- Каждые 30 секунд мок сам отправляет алерты по кругу: загорелся → повтор → прошёл → группа из нескольких → warning → …

`host.docker.internal` — это ваш компьютер, если смотреть изнутри контейнера. На macOS и Windows адрес работает сразу. На Linux нужен флаг `--add-host=host.docker.internal:host-gateway`, он уже есть в команде выше.

Через docker compose: возьмите [compose.yaml](compose.yaml) и запустите `docker compose up`.

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `TARGET_URL` | `http://host.docker.internal:8080/webhooks/grafana` | Куда отправлять. Можно поменять в интерфейсе без перезапуска |
| `AUTO` | `firing,firing,resolved,multi,warning,mixed,no_data,staging,resolved` | Какие сценарии слать автоматически и в каком порядке. `off` — не слать, только кнопками |
| `INTERVAL` | `30s` | Пауза между автоотправками |
| `AUTH_HEADER` | — | Значение заголовка `Authorization`, например `Bearer my-token` |
| `AUTH_USER`, `AUTH_PASSWORD` | — | Basic-авторизация, как в настройках контакт-поинта |
| `RETRIES` | `2` | Сколько раз повторить, если сервис ответил 5xx или не ответил |
| `TIMEOUT` | `10s` | Сколько ждать ответа на одну попытку |
| `RECEIVER` | `larek-webhook` | Имя контакт-поинта, попадает в `receiver` и `groupKey` |
| `GRAFANA_URL` | `https://grafana.k.larek.tech/` | Из этого адреса строятся `externalURL` и ссылки в алертах |
| `LISTEN` | `:3000` | Порт веб-интерфейса |

## Сценарии

| Имя | Что проверяет |
|---|---|
| `firing` | Один critical-алерт. Если отправить дважды, придёт тот же `fingerprint`, как при повторном уведомлении |
| `resolved` | Тот же алерт закончился: `status=resolved`, `endsAt` заполнен, `fingerprint` совпадает с `firing` |
| `mixed` | В одной группе один алерт горит, другой прошёл. Верхний `status` — `firing` |
| `multi` | Три алерта в одной группе (`HighLatency` у трёх сервисов) |
| `warning` | Severity `warning`: для проверки уровней уведомлений |
| `info` | Severity `info`: самый низкий уровень |
| `staging` | Тот же алерт, но в папке `staging`: для маршрутизации в разные чаты |
| `no_data` | Grafana не получила данные: `alertname=DatasourceNoData`, `values=null`, `state=no_data` |
| `datasource_error` | Запрос правила упал: `alertname=DatasourceError`, текст ошибки в `annotations.Error` |
| `empty_values` | Обычный алерт, но `values=null` и пустой `valueString` |
| `truncated` | `truncatedAlerts=7`: Grafana обрезала список по `max_alerts` |
| `custom_template` | В контакт-поинте свой шаблон: `title` и `message` с произвольным текстом |

Посмотреть JSON любого сценария:

```bash
docker run --rm ghcr.io/egortarasov/grafana-mock-webhook-service show mixed
```

Отправить один раз, например из теста или CI. Если ответ не 2xx, команда завершится с кодом 1:

```bash
docker run --rm --add-host=host.docker.internal:host-gateway \
  ghcr.io/egortarasov/grafana-mock-webhook-service \
  send -target http://host.docker.internal:8080/webhooks/grafana firing
```

## Как устроен запрос

Это `POST` с `Content-Type: application/json` и `User-Agent: Grafana`. Если заданы `AUTH_*`, мок добавляет `Authorization`.

```json
{
  "receiver": "larek-webhook",
  "status": "firing",
  "orgId": 1,
  "alerts": [
    {
      "status": "firing",
      "labels": { "alertname": "HighErrorRate", "service": "eggkiller", "severity": "critical", "...": "..." },
      "annotations": { "summary": "Доля 5xx у eggkiller выше 5%", "...": "..." },
      "startsAt": "2026-10-24T10:15:00Z",
      "endsAt": "0001-01-01T00:00:00Z",
      "fingerprint": "4ee26f38339c6c44",
      "values": { "A": 0.073, "B": 1 },
      "...": "..."
    }
  ],
  "groupLabels": { "alertname": "HighErrorRate", "grafana_folder": "prod" },
  "commonLabels": { "...": "..." },
  "commonAnnotations": {},
  "externalURL": "https://grafana.k.larek.tech/",
  "version": "1",
  "groupKey": "{}/{__grafana_autogenerated__=\"true\"}/{__grafana_receiver__=\"larek-webhook\"}:{alertname=\"HighErrorRate\", grafana_folder=\"prod\"}",
  "truncatedAlerts": 0,
  "title": "[FIRING:1] HighErrorRate prod (prod-eggkiller eggkiller critical)",
  "state": "alerting",
  "message": "**Firing**\n\nValue: A=0.073, B=1\n..."
}
```

Что важно для обработчика:

- **Опирайтесь на `alerts[]`.** Поля `title`, `message` и `state` остались для совместимости со старыми алертами Grafana.
- **Верхний `status`** — `firing`, если горит хотя бы один алерт в группе. Если прошли все, будет `resolved`.
- **`endsAt` = `0001-01-01T00:00:00Z`** означает, что алерт ещё не закончился.
- **`fingerprint`** не меняется у одного и того же алерта. По нему убирают дубли и находят пару firing → resolved.
- **`values`** — значения выражений правила (`A`, `B`…). Может быть `null`.
- **Повторы.** Если сервис ответил 5xx или не ответил, мок повторит запрос. На 4xx не повторяет. Возвращайте 2xx сразу после приёма, а отправку в Telegram делайте отдельно от ответа.

## Сборка из исходников

```bash
go test ./...
go run . serve
docker build -t grafana-mock-webhook-service .
```

Образ `ghcr.io/egortarasov/grafana-mock-webhook-service` (amd64 и arm64) собирает GitHub Actions на каждый push в `main` и на теги `v*`.
